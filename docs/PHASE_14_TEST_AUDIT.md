## 2. Identified Coverage & Edge-Case Gaps

Through a line-by-line audit across `app/`, `ml/`, and `streamlit_app/`, the following testing gaps were identified:

### A. Backend Core & Configuration (`app/`)
1. **Config & Environment Overrides**: Edge cases where environment variables override defaults or invalid types are supplied.
2. **Lifespan Initialization & Teardown**: Explicit testing of startup pre-warming failure handling and graceful shutdown.
3. **Middleware Boundary Conditions**:
   - `rate_limit.py`: Exact window rollover and rejection at threshold limit.
   - `timing.py` & `request_id.py`: Custom vs autogenerated `X-Request-ID` handling under high concurrency.
4. **Structured Error Handler Contracts**: Full validation of 404, 422, 429, 500, 503, 504 error response JSON contracts ensuring zero stack trace or internal path leaks.

### B. Recommendation Cache & Concurrency (`app/core/cache.py`)
1. **TTL Expiration & Eviction**: Testing time-based expiration and capacity eviction under bounded max size ($1,000$).
2. **Key Determinism with Complex Query Combinations**: Verifying that varying $\lambda$, cuisine order, spatial coordinate precision, or user IDs generate deterministic and distinct keys.
3. **Controlled Concurrency & Race Condition Prevention**: Multi-threaded read/write stress testing to guarantee thread safety.

### C. Public API End-to-End Matrix (`app/api/v1/`)
1. **Boundary & Malformed Inputs**:
   - Extreme `top_k` ($k=0, 51, 1000$).
   - Coordinates at geographic poles ($\pm 90^\circ, \pm 180^\circ$) and invalid floats (NaN, Inf).
   - Nonexistent / negative restaurant IDs and user IDs.
   - Negative budgets ($< ₹0$) and impossible ratings ($> 5.0$).
2. **Deterministic Response Ordering**: Asserting that identical requests return identically ordered slates.

### D. ML Pipeline & Data Integrity (`ml/`, `data/`)
1. **Catalog Completeness**: Validating exactly 12,481 rows, unique surrogate keys, and valid non-null columns.
2. **Synthetic Benchmark Integrity**: Verifying 600 unique users, zero train/test overlap, and rating scale $[1.0, 5.0]$.
3. **Explainability Grounding**: Asserting that explanations never reference un-triggered signals or claim real user behavior for synthetic SVD predictions.

## 3. Flakiness & Performance Dependency Analysis

1. **Timing Assertions**: Absolute millisecond thresholds can fail on overloaded CI environments. All performance assertions must use generous relative bounds or ratio speedup comparisons (e.g. cached query must be $\ge 2\times$ faster than uncached).
2. **Network Isolation**: All frontend tests must run in complete network isolation using mocked requests.
3. **Artifact Immutability**: Tests must strictly open dataset files in read-only mode (`r`) and never mutate disk artifacts.

## 4. Phase 14 Testing Strategy & Module Plan

We will create structured Phase 14 test modules:

1. `pytest.ini`: Configures strict markers (`unit`, `integration`, `api`, `ml`, `streamlit`, `e2e`, `performance`), warning filters, and discovery.
2. `tests/test_phase_14_backend_unit.py`: Config, middleware, error handlers, request tracing.
3. `tests/test_phase_14_cache_concurrency.py`: TTL expiration, LRU eviction, key determinism, multi-threaded safety.
4. `tests/test_phase_14_api_e2e.py`: Exhaustive endpoint test matrix across all 8 recommendation + 4 system endpoints.
5. `tests/test_phase_14_ml_pipeline_e2e.py`: Pipeline routing, MMR bounds, Bayesian quality, data integrity.
6. `tests/test_phase_14_security_robustness.py`: Payload bounds, injection resistance, boundary enforcement.
7. `tests/test_phase_14_performance_regression.py`: Lightweight benchmark thresholds marked `@pytest.mark.performance`.
